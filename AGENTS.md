## What this repository is

The single static site served at `fixtureflow.github.io`. It is a **shared monorepo**:
DDLC, CourtFlow and marketing all publish from it. Every deployed PWA portal, every
marketing page and the privacy documents live side by side on `main`.

There is no build step and no staging site. **A push to `main` is a production
deployment.**

---

## NON-NEGOTIABLE: never stage broadly

> [!CAUTION]
> **`git add .`, `git add -A` and `git commit -a` are strictly forbidden in this
> repository.**
>
> Three products deploy from here. A broad add sweeps another product's in-flight,
> unfinished work into your commit and pushes it live. Because a push to `main` is a
> deployment, that publishes someone else's half-finished portal to real users.

Always stage explicit paths:

```bash
git add courtflow/index.html          # correct — one named file
git add leagues/player leagues/club   # correct — named directories
git add .                             # FORBIDDEN
git add leagues/                      # FORBIDDEN — sweeps leagues/dev/ too
git add courtflow/                    # FORBIDDEN — sweeps courtflow/dev/ and play/
```

> [!WARNING]
> `leagues/` and `courtflow/` each contain **both** a dev and a production tree.
> Staging the parent directory crosses the dev/prod boundary in a single command.
> Name the leaf directories, never the parent.

Run `git status --short` before every commit and confirm the staged set is exactly
what you intend.

## Commit Convention

All commits follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/).

### Allowed types — and no others

```
feat  fix  docs  style  refactor  perf  test  build  ci  chore
```

This is the `@commitlint/config-conventional` set, which the Conventional Commits
spec itself defers to for types beyond `feat` and `fix`.

**Explicitly NOT allowed:**

| Do not use | Use instead | Why |
| :--- | :--- | :--- |
| `ref` | `refactor` | `ref` is a Sentry-house type, not a conventional one |
| `meta` | `chore` | Not in the conventional set |
| `license` | `chore` or `docs` | Not in the conventional set |

### Subject rules

- Imperative, present tense: *"Add retry guard"*, not *"Added retry guard"*.
- No trailing period. Maximum 70 characters.
- A **product scope is mandatory** — see the ownership table above. An unscoped
  commit in a shared monorepo does not say whose deployment it was.

### Prohibited in every commit

- **Never add `Co-Authored-By`, `Generated by AI`, or any other AI-attribution
  trailer.** This repository does not use them.
- **Never auto-create a branch to avoid committing on `main`.** If you believe a
  branch is needed, ask first.

## Release Marker Commits — NON-NEGOTIABLE FORMAT

If this repository ever carries its own version:

```
chore(release): vX.Y.Z - <Release Title>
```

- **`chore(release):` matches the semantic-release default**, which is
  `chore(release): ${nextRelease.version} [skip ci]\n\n${nextRelease.notes}`.
  ([semantic-release/git README](https://github.com/semantic-release/git#message))
- **`docs:` is wrong** — conventional-changelog presets filter `docs:` out of
  generated changelogs, so the release would vanish from generated history.
- **`feat(release):` is wrong** — under SemVer tooling `feat:` implies a minor bump,
  so a release commit would recursively imply another release.

The decision is closed; do not relitigate it.

> [!NOTE]
> PWA deployments into this repo are **not** releases. They are the *output* of a
> release performed in `ddlc-dev` or `courtflow-dev`. Use the product scope —
> `feat(ddlc): deploy production PWA v3.0.0` — not `chore(release):`.

## The waitlist endpoint is shared

`ddlc/script.js` and `courtflow/index.html` both POST to the **same** Apps Script
webhook, writing into the **same** sheet. The backend lives in a separate repository,
[`ddlc-marketing`](../ddlc-marketing), on a **different Google account**.

> [!WARNING]
> A change to the submission contract — field names, response handling, consent
> wording — affects **both** marketing pages. Fixing one and not the other is how the
> two drifted apart before. When you change one, check the other in the same sitting.
